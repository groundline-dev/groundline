# Only groundline's own failures are GroundlineErrors

Library callers catch `GroundlineError` to handle setup errors, invalid input and model failures, so an exception raised by the caller's own model client or custom stage, or by a bug in groundline, comes out as it was raised. Wrapping those too would let `except GroundlineError` hide the caller's own bugs, and keeping those apart is what the error types are for. The cost is that such an exception carries no record of what the check had spent before it stopped. A caller's model client reports a model failure by raising `ModelFailureError` itself.
