# AWS deployments upgrade in place, with data on its own volume

Every AWS deployment upgrades in place over SSM: the same server checks out the new commit and recreates its containers. It also keeps its Postgres data, Caddy certificates and database passwords on an EBS data volume, managed with an Elastic IP in a separate Terraform root (`infra/data/`), which the scripts refuse to delete except when deleting the deployment's data is what was asked for. We chose this over replacing the server on each upgrade because it is the conventional approach for a single Docker Compose server with a local database: upgrades are faster and nothing has to move between servers. The data volume still means a replaced server, whether on purpose or by accident, keeps its data, and it leaves operating system patching by root volume replacement open to ALL-113.
