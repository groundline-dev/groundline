# The SDK is generated with openapi-python-client

The SDK must follow the API without drifting, and its generator shapes its models and dependencies, so changing it later would break anyone using those models. We chose openapi-python-client (0.30.0, pinned in `uv.lock` as a dev dependency, so its ruff formatting step can't change the output) over OpenAPI Generator and Fern because it needs no Docker, Java or Node, has two runtime dependencies (attrs and httpx2), gives sync and async calls in one package, and had the fewest pyright strict errors (22, against about 960 and 128). We accept attrs models, which don't validate at runtime the way pydantic models do, and check the generated code at pyright's basic level while the hand-written code stays strict, because its 22 errors are type-inference gaps inside the generator's own output.
